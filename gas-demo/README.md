# 燃气公司智能问数 Demo（业务知识库）

> 定位：为「燃气经营与财务稽核」场景的智能问数路演提供业务知识、模拟 CSV 与本地数据集。
> 当前已提供 3 个主题数据集、9 张模拟表和一致的 43 节点组织树。历史设定见下文；实际生成口径以 07、08、09 文档及校验报告为准。

## 最新模拟数据（2026-10-23）

三个数据集已升级为 realism-v2 并写入 PG：9 张表共 **22,261 行**，管段 **12,000 条**。组织树与权限不变。详见[模拟场景与口径](docs/11_更真实的模拟数据场景.md)。下文 2026-10-22 的 10,501 行为历史装载记录。

## 当前可用内容

- `data/`：9 份 UTF-8 BOM CSV，共 22,261 行。
- `generated/organization_tree.json`：与 CSV 同源的系统组织树。
- `generated/feishu_sync_templates.json`：9 个停用同步任务模板，尚无飞书凭证和表 ID。
- `generated/datasets.json`、`views.sql`：3 个主题的数据集定义与 12 个数据库视图。
- `generated/validation_report.json`、`runtime_checks.json`：模型校验与本地运行检查。
- `docs/09_启动与飞书导入指南.md`：查看项目、导入飞书、授权及联调步骤。

本地预装数据不代表已从飞书同步。请先用现有超级管理员查看；普通账号需绑定燃气组织并完成取数前权限验收。

## 先用 PostgreSQL 问数（当前模式）

2026-10-22 已直接核对并幂等补写本地 PG：9 张 `raw_gas_*` 底表共 **10,501 行**，12 个 `v_gas_*` 查询视图。数据原先已预装，本次逐行比对一致，因此未重复插入；组织编码、名称、路径与系统的 **43 个燃气组织节点**一致。

三个已启用数据集保持原 ID：64 经营与供销差、65 应收回款与稽核、66 安全与管网治理。普通问数与高阶研究都读取 PG，业务答案继续经过真实 AI，不依赖飞书连接。

数据覆盖 **2024-01 至 2026-09**，演示时请明确月份。可以直接问“2026年9月各分公司销气量排名”“2026年9月末应收余额是多少”“截至2026年9月底有哪些超期未闭环隐患”。

`generated/pg_load_report.json` 保存实际表行数、视图和数据集映射校验；18 条数据库查询均执行成功，这些是数据库检查，不代替 AI 问数验收。

`load_postgres.py` 是独立的数据装载脚本，默认只核对，使用 `--apply` 才进行事务式补写；保留账号、权限、数据集 ID 和报告配置。若表中已有非本地模拟来源的记录则拒绝覆盖。

飞书接入暂缓。后续按相同字段名、类型和组织编码，将全量快照覆盖到相同 `raw_gas_*` 底表，继续复用视图和数据集。切换时须验证全量替换会移除本地模拟记录，不能将两套记录追加混存；若组织编码或层级变化，还需同步维护系统组织树。本轮未创建或启用飞书同步任务。

## 演示主体

**江城燃气股份有限公司（江城燃气）** —— 某华中省会城市的城市燃气经营主体，年供气约 19 亿方、服务 310 万居民用户。核心矛盾是**"规模大却不赚钱"**：年收入约 50 亿元，但因购销倒挂，净利润持续为负。

> 本 demo 为**虚构演示**：公司名称、组织、数字均为模拟，不指向任何真实企业；业务特征与指标体系反映的是城市燃气行业普遍关心的问题（购销倒挂、供销差、计量、回款、安全）。

## 历史落地设想（实际实施以 07~09 为准）

1. 按 `03_模拟数据集与数据表设计.md` 生成各表模拟数据 CSV；
2. 连同本目录知识文档，打包上传飞书（多维表格/云文档）；
3. 用系统功能同步到数据库（维度表 + 事实表）；
4. 接入智能问数，用 `04_智能问数场景题库.md` 作为预置问题与验收用例。
