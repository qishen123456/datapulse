# 燃气 Demo：启动与飞书导入指南

## 先查看本地项目

打开 http://localhost:8888/ask ，使用原来的超级管理员账号登录，密码未修改。

- 问数页：选择江城燃气相关预置问题。
- 数据集管理 `/datasets`：搜索“江城燃气”，可见经营与供销差、应收回款与稽核、安全与管网治理三个主题（本地 ID 64、65、66）。
- 组织树 `/organization-trees`：选择“江城燃气组织树”，应有 1 集团、6 分公司、12 服务中心、24 网格，共 43 节点。
- 飞书同步 `/feishu-sync`：后续创建实际同步任务的位置；当前九个模板在导入包中，未伪造连接配置。

现有服务前端 8888、后端 5002、数据库映射端口 5433。数据库卷未重建，其他数据集保留。本轮使用本地已有的双路径前端镜像和加入燃气接入修复的后端镜像。

同一台机器重启命令（从项目根目录运行）：

```sh
docker compose -f datapivot-demo/docker-compose.yml -f gas-demo/docker-compose.preview.yml up -d --no-deps --no-build backend frontend
```

此 override 引用本机已构建镜像；全新机器需先按主项目说明构建镜像，不能直接假设这些本地标签存在。数据安装不是应用每次启动时自动执行。

## 三个立即可验证的问题

1. 2026 年 9 月各分公司销气量排名。
2. 2026 年 9 月欠费最多的十个模拟工商客户。
3. 截至 2026 年 9 月底有哪些超期未闭环隐患。

本地已执行 18 条金标 SQL，并通过登录后的 HTTP 查询预览接口核对；未据此宣称真实模型的自然语言回答已经全部验收。数据截止 2026-09，本月/上月可能超出数据范围，建议初次演示明确写月份。

## 组织结构如何保持一致

`scripts/generate_demo.py` 中只定义一棵组织树，同时派生 CSV 和系统组织 JSON。每条事实的 `org_id` 必须存在于组织树，名称/路径/父节点一致才允许安装。实际安装后再次从系统读回 43 节点，与落库组织源逐条核对。

销售与应收落到有销售职责的 20 个网格；采购和损益落到服务中心，安全/资产覆盖全部 24 网格。高压输配仍存在于组织树与安全/成本表，但没有虚构的居民销售记录。因此“每个组织在所有表都有数据”不是验收条件，粒度和职责一致才是。

三个数据集均已绑定燃气组织树。未绑定燃气组织的普通账号无权访问。当前未创建新员工账号，也没有把现有员工自动挂到燃气组织。分公司、中心、网格账号上线前，仍需单独验证汇总、缓存、导出和高阶各分支都在聚合前过滤；当前仅验证了授权成员判定，未将它冒充完整行权限验收。

## 你在飞书需要做什么

1. 在飞书创建一个**多维表格**文件，命名“江城燃气问数 Demo”。不要建成普通电子表格。
2. 将 `data/` 下九份 CSV 分别导入为九张数据表，保留第一行英文字段名。不要将九份文件追加到同一张表。
3. 按 `08_字段字典与飞书类型.md` 核对类型。业务键、组织编码、路径、月份是文本；金额、数量是数字；日期是日期。缺失日期留空，不填 0。
4. 创建或复用企业自建应用，申请读取多维表格记录与字段的权限，完成需要的发布/审批步骤。
5. 由文档所有者或可管理者将应用添加为这个多维表格的协作者，并配置读取所需授权。若启用高级权限，核对具体表和字段是否可读。API 权限和这个文件的文档权限都必须具备。
6. 复制九张表的链接。系统中 `base_id` 是链接的 Base app_token，`table_id` 是每张表的 Table ID；它们不是开放平台 App ID。第一次接入 `view_id` 留空。
7. 在系统本地填写应用凭证，不把 Secret 发到聊天、填进 CSV 或提交 Git。

授权入口以你飞书当前界面为准，可参考 [官方云文档权限常见问题](https://www.feishu.cn/hc/zh-CN/articles/360044508113-云文档权限常见问题)。行数权益按租户版本核对，当前每张表均低于 4,000 行。

## 同步任务怎么填

`generated/feishu_sync_templates.json` 提供九个任务的名称、目标表、全量模式和 60 分钟频率。凭证与真实表 ID 未填，因此这些是待接入模板，不是已经运行成功的任务。

例：飞书表 `gas_sales_monthly` → 系统任务“江城燃气·gas_sales_monthly” → 目标表 `raw_gas_sales_monthly`。其余八张采用同一映射规则。原始表名称与本地预装保持一致，首次成功全量同步将替换这张表的本地模拟快照，业务视图无需改名。

先保持任务停用，检测连接、预览字段，手动同步并核对记录数，再启用定时。九表全部同步成功且版本一致后再开始正式问数；本轮尚未实现九表作为一个原子批次发布，不要在半数表同步时演示跨表结果。

已修复全量成功读取空表仍残留旧记录的问题；读取失败不会当空表清空。增量模式仍是按飞书 record_id 更新，不负责源端删除，因此本 Demo 推荐全量。飞书整表重新追加导入可能换 record_id；必须检查 business_key 不重复。

## 本地资产和复现

```sh
python3 gas-demo/scripts/generate_demo.py
python3 gas-demo/scripts/prepare_runtime.py
python3 -m unittest discover -s gas-demo/scripts -p 'test_*.py'
```

第一步生成中间模型和组织/校验文件；CSV 导出由 `scripts/export_csv.mjs` 使用当前 Codex 提供的 artifact-tool 运行时完成，九份成品已在 `data/`。不要将本地安装脚本当成飞书同步脚本，也不要在源表已经接入真实记录后重新灌入本地种子。

`install_local.py` 只管理 `raw_gas_*`、`GAS_*` 元数据及燃气组织树，不清理其他主题。安装前组织树与权限文件备份在主项目 `backups/gas-demo/`。原始表/视图/元数据在一个数据库事务内提交，配置合并另行备份并验证；不宣称配置文件和数据库具备跨存储事务。

所有公司、客户、经营和安全数字均为虚构，数据用于问数链路与计算验证。
