# 07 · 三数据集与飞书同步实施计划（待确认）

日期：2026-10-21。此文件是实施计划，本轮未生成 CSV、创建业务数据集、写入飞书或启动同步。

## 1. 推荐落地方式

**1 个飞书多维表格文件（Base）→ 9 张数据表 / 9 份 CSV → 9 个同步任务 → PostgreSQL 原始表 → 类型化及业务视图 → 3 个问数数据集。**

三个数据集是三个业务入口，不是只准备三张大表。CSV 是你在飞书维护的原始业务数据，系统查询的是同步落库后经过整理的视图；修改飞书记录、重新同步后，问数结果应随之更新。

保留既有总主理人 + 专家框架。三个主题均可使用普通问数和高阶分析，均绑定同一套燃气组织树和权限规则；高阶跨主题取证必须逐个检查数据集授权，不能借其他主题越权取数。

## 4. 九份 CSV 设计

时间统一为 2024-01 至 2026-09，共 33 个月；“最新月”固定为 2026-09。截止日之后的“本月”明确提示暂无数据，不把 10 月空值解释成业绩下降。

| CSV / 飞书表 | 一行代表什么 | 预计行数 | 关键内容 |
|---|---|---:|---|
| gas_org.csv | 一个组织节点 | 43 | 集团→6 分公司→12 中心→24 网格；org_id、parent_id、level、path |
| gas_sales_monthly.csv | 月×网格×4 类客户 | 3,168 | 售气量、加权售价、账单收入、实抄/估抄量、税口径；业务主键 |
| gas_supply_monthly.csv | 月×服务中心×3 类气源 | 1,188 | 组织边界入口计量气量、分摊采购成本、气源、单价、分摊标识、适用演示阈值 |
| gas_profit_monthly.csv | 月×服务中心 | 396 | 安装/增值收入及对应直接成本、配气成本、管理/财务费用、减值、目标值；销气与采购取其他表汇总 |
| gas_ar_monthly.csv | 月×应收对象 | 约 4,000 | 约 120 个对象（工商模拟客户 + 居民汇总桶），期初、开票、回款、调整、期末、5 段账龄、计提、催收状态 |
| gas_growth_monthly.csv | 月×服务中心×4 类客户 | 1,584 | 期初/期末户数、新增/销户、报装/通气、瓶改管、潜在可接入户数 |
| gas_safety_monthly.csv | 月×网格 | 792 | 应检/已检/到访不遇、三件套安装、抢修次数/及时数、泄漏次数 |
| gas_hazard_orders.csv | 一条隐患工单 | 约 120 | 发现时间、截止时间、完成时间、级别、网格、关联管段、状态 |
| gas_network_assets.csv | 一条管段资产 | 约 240 | 网格、压力等级、管材、敷设日期、里程、GIS 入库日期 |

每份 CSV 包含稳定的 `business_key`，适用表带 `month`、`org_id`、`org_path`，并记录模拟版本。飞书记录 ID 由平台产生，不能替代业务唯一键。编码为 UTF-8 BOM，字段名固定为英文，另交付中文字段字典与飞书字段类型表。日期采用 ISO 格式；月键采用 YYYY-MM 文本；金额和数量使用十进制，缺失与零分开。

预计每张表均少于 5,000 行，但导入前仍核对你所在租户的实际行数权益。应收不是 310 万客户的全量明细：居民桶明确标识为汇总，工商客户为模拟客户池；只能在这个范围内做“欠费前十”，不能宣称是真实全量客户排名。用户总数由增长表承担。

高压输配是运营组织，不能机械分配居民销气。保留六分公司组织树，销售终端只落有销售职责的网格；上述行数为上限，生成时允许无销售职责网格不产销气记录。集团采购按演示规则分摊到中心，同时提供边界计量量；分摊成本与实测损耗区别展示，不能拿成本分摊气量伪装实测漏损。

## 5. 生成前必须修正的业务口径

1. **单位错误**：原 06 文档的 `万方×元/方×10=万元` 不正确，应是 `万方×元/方=万元`。底层统一方、元，展示时转换万方、万元，避免十倍偏差。
2. **规模以计算结果为准**：年气量锚定 18.5 亿方，居民约 49%，收入按量价真实推导，不同时硬凑“收入 50 亿”等冲突锚点。季节权重先归一化，再分配年度气量。
3. **成本不可重复**：购气成本按采购气量核算；输配、管输费用分别定义，重复项不得同时计入采购和配气成本。利润 = 全部收入 − 对应直接成本 − 配气及期间费用 − 减值。没有税项时称“模拟税前利润”，不冒称净利润。
4. **供销差边界一致**：同月同组织入口量与销气量对比；简化库存、压力温度与跨月抄表影响的假设写入字典。加权比率用总量相除，不平均各组织百分比。
5. **3.5% / 4.5% 是演示核定阈值**：不沿用旧文档“全国通用硬标准”的断言，不把价格监管核定参数等同真实安全/漏损判定标准。
6. **应收闭环**：期末 = 期初 + 本期应收 − 本期回款 + 调整；账龄段合计等于期末；前月期末等于次月期初。存量应收只取选定月末，不能跨月累计。
7. **稽核差异单独存**：保留理论量价收入、账单实际收入、差额及原因；预置异常登记在校验清单，其他勾稽必须通过。不能为了异常案例让所有校验失效。
8. **证据边界**：估抄、老旧管网与供销差相关只能提示待核查；没有案件/复核数据，不回答“已证实偷盗气”。三单一致、IC 卡复核、追缴等题目列入第二期，不用现有月报编造明细。
9. **时间口径**：2026 年仅到 9 月，同比用同一期间；GIS 用入库日期回放历史；整改率区分当期新增、存量关闭和到期闭环。

## 6. 飞书授权：三个层次分别做

### 6.1 飞书应用的 API 权限

在飞书开放平台创建或复用企业自建应用，使用应用凭证取得 tenant_access_token，符合当前代码认证方式。为列出字段、读取记录申请对应只读权限，优先检查 `bitable:app:readonly`；最终以官方接口页面支持的权限及租户审批结果为准。完成版本发布、企业审批等生效步骤。

本期只读飞书，不需要为了同步申请写入、删除全部多维表格的权限。App Secret 在系统的凭证配置中输入，不放 CSV、方案或 Git 中；联调检查返回数据/日志是否脱敏。

### 6.2 目标 Base 的文档授权

新建“江城燃气问数 Demo”多维表格文件，把九份 CSV 分别导入九张数据表。由所有者或可管理者按官方指引把应用添加为目标文档协作者，授予读取所需权限。应用拥有 API 读取能力，不代表自动能读取你的这个 Base。高级权限开启时还要核对相应表/字段的可读范围。

优先使用直接 Base 链接；每张数据表保留链接里的 Table ID。系统 `base_id` 对应 API 的 app_token，**不同于**开放平台 App ID。第一轮 View ID 留空，避免视图筛选导致漏同步。

### 6.3 本系统的组织数据权限

复用组织树维护能力，导入/维护 43 个节点，三个数据集均配置组织字段，并绑定集团、分公司、中心、网格的测试账号。飞书用一个应用读取源数据，不能据此推导问数用户有全集团权限。

必须验证权限在明细取数和聚合之前生效。当前 data_permission_store 存在外层包裹 SQL 的过滤方式与路径子串匹配，不能仅新增 org_path 就认定隔离完整；需检查现有执行链路，必要时改成授权组织 ID 集合的精确过滤，覆盖汇总、排名、缓存、高阶各分支和导出。网格长不看只到中心粒度的利润/采购表，也不把中心汇总复制到每个网格。

## 7. 同步任务和视图实施

每个 CSV 对应同名飞书表及一个独立同步任务：例如 gas_sales_monthly → `raw_gas_sales_monthly`。统一 `raw_gas_` 前缀，不碰其他演示数据。九个任务初始停用，连接预览成功后逐个手动全量同步；联调通过再设每 60 分钟运行（可调整）。飞书 CSV 重复导入可能生成不同 record_id，因此验证 business_key 去重，推荐编辑原记录而非整表反复追加。

第一阶段顺序：组织 → 各业务源表 → 原始行数/字段验证 → 类型化视图 → 业务汇总视图 → 数据集字段/Schema/权限 → 问数。跨源表业务视图需全部源表就绪后发布，防止“销售新批次 + 采购旧批次”混算；增加本次演示批次/数据版本检查，全部成功后才标记数据就绪。

类型化视图处理空字符串、数值、日期、非法值；非法值可追到源记录，不静默当零。经营损益与供销差计算先分别聚合，避免 4 类客户×3 个气源造成重复金额。原始表保留 record_id 与同步时间，结果可追到来源。

不用飞书筛选视图替代系统权限。普通 PostgreSQL 视图在原始数据提交后自然更新，优先使用它；首次不引入物化视图刷新和额外定时层。转换服务的自动触发不能破坏视图依赖。
