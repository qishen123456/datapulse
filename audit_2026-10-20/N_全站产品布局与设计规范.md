# DataPulse 全站产品布局与设计规范

本轮交付为布局设计与可交互预览，尚未替换运行中的业务界面。预览中的配置、发送、运行按钮只做本地交互，不写入系统，不代表真实 AI 执行。

## 设计判断

目前的割裂来自页面结构：十多个模块平铺在顶部；全局上下文栏与问数自身头部重复；数据集、智能体、飞书同步、组织树、控制台各有不同的横幅、统计卡和编辑区。只统一配色无法解决定位、层级与密度问题。

推荐采用「完整工作台」：深色分组侧栏、浅色工作区、统一顶部工具条与页面标题。第二种「专注工作台」采用窄导航轨道加当前分组的二级导航，适合熟练分析用户。两种布局共用页面模板与权限过滤，不能形成两套功能实现。

设计借鉴的是可验证的产品模式：[Carbon UI Shell](https://v10.carbondesignsystem.com/components/UI-shell-left-panel/usage/) 的全局头部与侧栏分工；[火山引擎 DataAgent](https://docs.volcengine.com/docs/Dataagent?lang=zh) 对分析、数据准备、配置和运维任务的划分；[数据集配置文档](https://docs.volcengine.com/docs/DataAgentPrivate/Datasetconfiguration-1?lang=zh) 对语义配置与知识准备的组织。下面的模块映射与交互方案是针对本项目的设计，不代表这些产品提供完全相同的功能。

## 一套框架，三种页面模板

### 分析画布

问数的主要空间用于问题、结论、证据图表和追问。普通问数与高阶研究是两个明确的任务入口，分别保持原有执行流程；高阶额外展示计划、并行分支、证据及研究报告。组织范围对两种路径均有效。

最近分析从按钮打开历史抽屉，不再与全局导航、过程栏同时形成三条常驻侧栏。过程在需要时打开右侧面板，提供「进展 / 查询依据 / 诊断」；面板与答案共享任务状态，失败与部分成功不能展示已交付。普通问数的过程摘要保持紧凑，高阶可下钻到分支与证据。

输入框始终可编辑。任务执行时允许提交至现有队列，展示排队数量、暂停和恢复；发送、停止、只读与队列权限使用现有控制台策略。当前任务完成时不得覆盖用户的新草稿。跑马灯只表示运行状态，不编造节点与完成比例；关闭动效偏好时保留静态状态文字。

### 资产列表与配置详情

数据集首屏负责找资产：搜索、领域筛选、可用范围与进入管理。三个燃气数据集单独列出；字段数、指标数表示配置规模，不等同于查询准确率。未连接的飞书任务显示待接入，不伪造同步成功。

点击资产进入详情，保留名称、返回入口与主操作，配置分为概览、字段与关联、指标口径、权限范围、样例查询。大屏可显示简洁的资产概况；窄屏将重要信息纳入正文，不仅隐藏。编辑页有未保存变更时必须提供状态与离开保护。保存成功后明确更新时间，验证失败定位字段。

数据源、模型、模板和同步任务沿用这一结构，避免各自重新设计横幅与统计区。凭证只通过安全输入与掩码展示，不进入预览、日志或快捷搜索。

### 治理与运维工作区

组织树采用左树右详情；智能体采用左角色右配置。两者保留局部上下文，不再塞入全部列表和全部表单。

系统控制台按问数策略、功能开关、字段可见性、运行日志组织。预览中的分组是信息架构提案，实施时映射到现有字段与接口；不得把所有示例文字直接创建为新开关。问数队列沿用发送、停止、只读等实际策略。发布与恢复必须展示真实校验结果，不能用固定绿色状态代替。

## 视觉规格

| 项目 | 规格 |
| --- | --- |
| 全局侧栏 | 桌面约 200–216px；专注布局约 64px；小屏改抽屉 |
| 顶部工具条 | 56–62px；面包屑、模块搜索、账号与工作空间；移除常驻秒级时钟 |
| 页面头部 | 标题 24–28px；一句用途说明；右侧一个主要操作 |
| 内容间距 | 8px 基线；页面边距 24–32px；相关控件 8–12px；区域间 20–28px |
| 字体 | 正文 13–14px；辅助信息 11–12px；标题 500 字重；关键数值等宽数字 |
| 表面 | 浅灰工作背景、白色内容面、深蓝灰导航；深色模式使用对应语义色 |
| 交互色 | 蓝色用于主要动作与选中；成功、警告、失败同时配文字，不能只靠颜色 |
| 容器 | 细边框、6–12px 圆角、轻阴影；通过留白和分割线组织，不堆叠嵌套卡片 |
| 数据表 | 稳定的行高、表头层级、数字对齐；操作收在尾列；小屏只在表格内横向滚动 |
| 过程面板 | 约 360–400px，按需打开；小屏用覆盖面板，保留关闭与返回 |

当前交互预览使用更适合对比设计的固定示例内容；生产页面需要加载中、空数据、失败、权限不足、保存中、未保存、部分完成和成功等完整状态。

## 高级感来自具体细节

- 全局搜索支持 ⌘K / Ctrl+K，先定位授权模块；后续可增加授权资产搜索，不能绕过服务端权限。
- 选中项、面包屑、页面标题与当前工作对象同步更新；刷新与返回保持可解释的位置。
- 列表选择后保留筛选与滚动位置；局部保存不重置整个工作区。
- 异步动作只锁定相关按钮，提供取消或重试入口；提交成功和失败在动作附近反馈。
- 数值、单位、时间范围与组织范围放在结果附近，便于核验；不使用大面积低对比度紫色正文。
- 动效只用于开合、切换与状态变化，约 120–200ms；尊重 reduced-motion，不靠无限动画维持“智能感”。
- 业务用户只看到授权的分析入口；管理员看到资产、编排与治理入口。界面隐藏不能代替服务端校验。

## 改造顺序与验收

1. **全局框架**：重构 App 布局与统一导航配置，保留所有原路由、角色和功能策略；删除重复上下文栏。保持 AskDesk 的 keep-alive 与任务生命周期，路由切换不能销毁运行任务、草稿或队列。
2. **分析工作区**：把现有普通/高阶流程放入新框架，保留真实 AI、组织校验、过程事件、查询依据、停止和排队能力。分别验证成功、空结果、部分完成、失败及等待确认；状态只能有同一份事实来源。
3. **资产与编排页面**：先改数据集，再复用列表、详情、编辑栏、页头与表单组件覆盖数据源、模型、智能体、模板和同步；同步能力只改交互，不提前接入飞书。
4. **治理与运维**：统一树形工作区、策略表单、日志与发布界面，核对控制台开关即时影响问数与查询。后端权限过滤、接口投影与前端可见性一致。
5. **全站验收**：1440、1024、768、390、320px；键盘与焦点；深浅主题；中文长名称；不同角色；路由返回；未保存保护；任务执行中导航切换；队列暂停恢复；真实 AI 问数回归。

预览已检查 13 个模块切换、资产详情口径页、快捷搜索及手机排版；这是布局验证，不替代实际系统的接口与权限验收。
