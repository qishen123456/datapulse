# 燃气真实问数回归测试

2026-10-22。使用当前本地后台、真实模型服务及 PostgreSQL 的燃气模拟数据进行 HTTP/SSE 验收，不使用接口夹具或缓存答案。

## 已核对场景

| 场景 | 验证内容 | 结果 |
|---|---|---|
| 自由措辞销气量排名 | 2026-09，5家销售分公司，逐公司气量与PG独立聚合一致 | 通过 |
| 月末应收汇总 | 2026-09，356,614,211.92元，不跨月累加余额 | 通过，修复报告后复测 |
| 安检覆盖率 | 6家分公司，以已检总户数/应检总户数计算0–1小数，逐公司与PG一致 | 通过 |
| 无数据月份 | 严格查询2026-10，返回0行，明确没有匹配数据，不偷换成9月、不认定业务值为0 | 通过 |
| 连续追问 | 先问9月末应收，再说“只看沙湖，保持刚才的月份和指标”；实际SQL保留2026-09且仅选沙湖，余额113,361,975.40元 | 修复后通过 |
| 高阶计划 | 必须经过AI，返回2个验证方向，用户确认前没有取证数据集结果 | 通过 |
| 高阶取证与报告 | 两路取数、AI解读、研究汇总及独立报告复核 | **尚未完整通过**：最新轮两路取数及报告复核已返回，但销气量分支AI解读失败 |

所有普通问数用例同时检查真实 `agent2.sql_generate`、`agent4.analysis` 模型响应及 `analysis_status=model_generated`，不能只凭接口200或返回数字判通过。

## 发现并处理

1. “保持刚才的月份”不在旧追问识别范围，且旧组织主体重写可能丢掉继承的时间/指标。补充通用前文引用识别，在用户明确沿用上下文时保留继承范围，不再被组织改写覆盖。
2. 通用数据集仍套用旧“业绩分析报告”四段式模板，单值回答被扩写成不相关诊断。通用模板改为先回答当前问题，仅根据当前数据输出，不强行生成亮点、问题或建议。
3. AI把管理员全域汇总误判为缺少组织过滤。将服务端实际身份范围与权限处理时机交给SQL审核和解读节点；仅修正模型上下文，不移除权限检查或修改权限过滤函数。
4. 首轮研究摘要把单月排名差异写成相关性、管理异常或系统性原因。加强报告生成契约：没有统计检验不能声称相关性，原因必须作为待验证假设，正文也必须保留证据边界。
5. 研究汇总模型调用补充真实trace，便于确认最终研究摘要也实际经过AI。
6. 提示词修订后的摘要仍出现对接近2.5%的几个对象做错误细微排名，因此增加独立AI报告复核。复核依据原始分支证据检查数值、单位、排序、引用和因果边界；复核失败时只保留事实数据，明确标记摘要复核缺口，不交付未经复核的草稿。复核是流程中的独立步骤，不是用固定延时模拟过程。

7. 后续真实复测遇到一次模型连接失败与分支证据不足，该次未记为通过，保存为 `report_review_attempt_failure.json`。排查发现旧SQL审核存在拒绝后仍放行原SQL的逻辑，现已移除：模型拒绝/不可用不能改写为approved=true；同时向审核节点提供真实字段字典和表结构，减少因缺少Schema而猜测字段。

8. 严格审核后，估抄率分支因视图口径审核被拒绝，暴露“审核拒绝后直接结束、没有反馈修复”的缺口。增加基于审核意见的SQL修复并重新审核；修复共享全任务最多两次预算，拒绝后绝不执行原SQL。失败时报告明确说“本次取证未完成”，不推断源库没有数据。记录保存在 `strict_review_attempt_failure.json`。

9. 最新轮两路查询及独立报告复核均有结果，复核后的摘要正确表达“沙湖约12%，其余四家基本接近2.5%”，不再强行排列近似值或认定管理原因。但销气量分支出现 `model_unavailable`，原逻辑仍把该分支标成completed。现收紧为只有 `analysis_status=model_generated` 的分支才可列入已完成研究证据；AI解读失败必须显示insufficient并形成缺口。新增回归测试验证这一状态。

## 当前结论

普通问数5个场景及高阶计划已取得真实通过记录；**高阶完整链路仍未稳定通过**，不能把该项写成全部成功。已完成两路SQL取数、真实研究汇总及真实独立报告复核的验证；最新失败点为分支模型解读未完成。最后的状态收紧改动已通过隔离回归并部署，尚未再执行一整轮真实高阶模型调用。失败样本保存在 `analysis_unavailable_failure.json`，当前清单 `results.json` 保留H02失败状态。

本轮模型服务发生过连接错误及解读未完成；不能用数值取回成功替代AI完成判定。普通场景的通过记录来自本轮此前的实机测试，最后的审核/状态修复后没有重新重复全部普通模型调用。

补充回归测试后，后端53项隔离测试通过。已更新本地后端部署。

## 验收方法与边界

- 脚本：`gas-demo/scripts/test_live_questions.py`。模拟数据的期待值使用固定PG查询独立计算，不复用AI SQL计算期待值。
- 普通问数独立场景最多两路并发；追问使用页面同样的客户端会话ID。初轮脚本遗漏会话ID，追问项当时未执行；修正验收脚本后才进行带上下文的实测，未将脚本问题记为产品失败。
- 首轮记录保存在 `generated/question_tests/initial_results.json`，首轮研究文本保存在 `initial_H02_research.json`；最终结果及业务证据按用例分别保存。不保存凭据、完整模型提示词或思维链。
- 本轮使用超级管理员授权，不能据此宣称普通员工账号的聚合前行级隔离已验收。
- 全部为虚构燃气演示数据；仅验证已列明场景，不代表所有自然语言问法均正确。
