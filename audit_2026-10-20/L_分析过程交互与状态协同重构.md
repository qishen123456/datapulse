## 原问题与修复

1. 后台仅按顶层 `error` 判断任务是否完成，导致生成/审核失败藏在结果集内时仍返回完成状态。新增 `outcome`，区分运行中、待确认、成功、成功但空结果、部分结果、失败与取消；最终 SSE 事件先广播终态，结果体使用同一状态。
2. 主区把消息不再 loading 当成“已交付”。主区、侧栏、输入框状态和历史任务改用一致的业务结果判断；旧历史结果可从查询、审核及解读状态推导。
3. 重试次数与数据集 ID 不一致时，同一个逻辑步骤出现多行。展示按 run、分支、数据集与逻辑节点合并尝试；缺失数据集 ID 的事件仅在归属唯一时合并，不将不同数据集或不同并行分支混为一谈。
4. 任务结束后遗留 running/retry 状态。未收到成功确认的步骤标记未完成；缺少记录的阶段标记未单独记录。既不保留终态中的动效，也不补造成功事件。
5. 右侧同时塞入日志和旧报告，各自滚动且重复显示。移除侧栏内的重复报告，改成一个滚动工作区。

## 新交互

- 普通问数主区：理解问题 → 准备查询 → 查询与核验 → 形成回答。四阶段条支持点击定位右侧相应阶段。
- 侧栏顶部：本轮最终状态、说明、基于真实时间戳的耗时、实际步骤/结果行数。
- 进展页：四阶段纵向路径、当前阶段的专家/Skills 与步骤明细；默认跟随事件，用户手动选择阶段后停止抢焦点，可主动恢复跟随。
- 查询依据页：按结果集查看实际 SQL、审核结论；运行时尚未返回结果可查看已生成的查询。
- 诊断页：集中显示未通过、需关注与中断项，一键定位阶段；技术事件默认折叠。
- 重试动作：把原问题填回输入框供用户修改，不静默重新发送。
- 手机端：侧栏覆盖工作区并使用可用屏幕高度，提供固定关闭入口与单一内部滚动区域。
- 开关约束：侧栏入口遵守执行详情开关；SQL/诊断页遵守 SQL 可见性策略；重试遵守发送、快捷提问、只读及运行状态；下载权限沿用主画布和研究报告。
