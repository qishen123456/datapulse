## 3. 最严重缺陷清单（按严重度）

1. **P0 执行层无资源闸门**：`execute_sql_for_source` 无超时/行数/成本限制（datasource_router.py:192-201）。
2. **P0 无持久化任务状态/会话状态**：重启即丢；跨会话恢复依赖前端 localStorage；无检查点（four_agent_ask.py:9034/9040；short_term_memory.py:10）。
3. **P1 只读安全为正则级**：可绕过多态（SELECT INTO、函数副作用），且无 AST 解析（ask_engine_sql.py:54-71）。
4. **P1 业务正确性无程序验证**：粒度/重复计数/时间边界/分子分母仅靠 Agent3 LLM 自审（8551）。
5. **P1 记忆=消息历史拼接**：非结构化状态，"删除过滤条件"类追问无法表达（short_term_memory.py:95-117）。
6. **P2 规则路径与数据集硬耦合**：`_build_online_sql`/`_build_consumer_business_sql` 等构建器绑定特定业务（four_agent_ask.py:6372/6827），系统可扩展性差。
7. **P2 检索非语义**：Golden SQL/常见问题 token 打分（bookshelf_repository.py:248），Chroma/Vanna 仅遗留链路使用（vanna_core.py；datasource_router.py:203-227），主链路未用向量召回。
8. **P2 无测试**：backend 无 tests 目录；准确率无度量。

## 5. 双模式现状（关键发现）

- `AskFlowController.decide`（ask_flow/controller.py:90-113）：用户请求 flow > 数据集策略 > 默认 flow；advanced 需 `advancedEnabled`+角色白名单+feature flag，默认**关闭**（DEFAULT_ASK_FLOW_CONFIG line 15-22）。
- advanced 模式（datapulse_advanced/service.py）实为"**basic 流水线 + skills 叠加层**"：dataset_route → route_guard → golden_sql → asset_pack/planner/sql_quality/self_check/evidence_vote/pandas_analyze/conclusion_advice 等技能按配置开关组装（`_run_advanced_trace`:625），最后仍回退 basic ask，再做跨数据集对比等后处理（`_execute_cross_dataset_compare`:259）。
- 结论：**当前不存在"主理人+专家"编排**。四 Agent 是固定串行流水线；advanced 是可插拔技能层。两者共享同一套资产/执行/日志底座（这是好底子）。
