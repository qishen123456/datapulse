## 为什么之前问不了

1. 真实普通问数入口返回 500：`BasicAskService.ask()` 在使用模块导入的 `scope_key` 后又在函数内部导入同名符号，触发 Python 局部变量未赋值错误。已改为模块级导入，并补覆盖生产包装分支的回归测试。
2. 原默认模型 `api.edgefn.net` 本机访问返回 403 / ACCESS DENIED；普通流程只能沿金标与兜底摘要返回。已读取用户指定的根目录《模型服务》文件，验证现有接入，切换本地默认到硅基流动 `Qwen/Qwen3.8-27B`。凭证经已有配置管理器加密保存，原配置已在 `datapivot-demo/backups/runtime/` 备份，未写入源码。
3. 新燃气数据集未配置专属报告时，原来会继承销售组织的“任务金额 / 达成率”模板；即使 SQL 正确，也会生成不相干的报告。现改为通用报告契约，保留已有显式配置，但不再替新数据集补造销售指标。

上一轮只验证 SQL 预览，未验证真实提问入口，不能据此宣称完整问数可用。本轮已补真实 HTTP 和浏览器端到端验证。

## 新的感官与交互

- 深色分析记录侧栏、浅色分析桌面、靛蓝操作与图表色；问数页的新视觉独立于其他管理页面。
- 首屏展示当前路径的用途和实际已授权问题，不以虚构业务数字装饰首页。
- 普通问数以“结论速览 / 查询事实 + 图表 / 数据 / 解读 + 来源”为一个完整答案。多结果集可切换，图表可选指标和条形 / 折线，表格支持排序、分页，导出保留本次真实结果。
- 高阶研究先呈现研究任务书，用户选择验证方向并确认。实际取证后才展示并行分支、状态与发现；最终报告分为结论摘要、证据索引、边界与待补证，每条发现可回到分支数据。
- 研究报告可下载为自包含 HTML，含证据链接、数据表及许可范围内的离线图表；不带 SQL、模型内部推理或凭证。普通简报与 CSV 导出同样转义来源内容，CSV 文本额外防止公式注入。
- 空值保持为空，不补成零；负数不隐藏；只有真实单行数值才显示单值指标，不把未知粒度的明细强行合计成 KPI。

## 两条真实执行路径的对应关系

### 普通问数

完全匹配的高质量金标问题先走确定性分支：当前身份 / 数据集授权 → 完整问题匹配 → 字段与口径 → 只读 / 字段校验 → 当前组织过滤 → EXPLAIN / 受控执行 → 数据断言 → 事实简报。每次重新执行数据库，不缓存业务行，也不把近似问题套入现成 SQL。无法唯一匹配则进入原有专家生成与复核链路。

这不是把普通流程简化成一个无护栏查询；只是完整匹配时不再多次等待模型。改了月份、条件或问法，不会随意复用旧 SQL。

### 高阶研究

主理人读取授权资产并规划 → 用户确认方向 → 专家并发取证 → 复核结果和独立证据 → 汇合摘要 → 研究报告。未完成分支列为待补证；同一 SQL 的重复分支不计作独立验证；高阶失败不暗中改为普通问数。

模型无法产生有效计划时明确返回未完成，不临时拼出“基线核验”冒充研究计划。研究摘要要求结构化 JSON，避免历史 Markdown 提示词使摘要解析失败。描述性差异和相关性不被包装成因果证明或预测精度。
