## 一、候选客户 / 合作方细分（4 类）

| 编号 | 细分 | 一句话画像 | 与 DataPulse 的关系 |
|---|---|---|---|
| **S1** | 飞书原生、无 BI 团队的中型制造/消费品企业 | 300–2000 人，业务数据全在飞书多维表格，老板和销售管理靠人肉导表看数 | **直接买家**（终端客户） |
| **S2** | 数据咨询 / 实施服务商（ISV、飞书服务商） | 给企业做数字化转型和报表实施，每个项目都要重写 NL2SQL 或硬编码指标 | **合作方**（交付加速器，DataPulse 是其军火） |
| **S3** | 有存量企业客户的 SaaS 渠道商 / 代理商 | 手里有几十上百家企业客户，缺一个客单价高、可私有部署的 AI 数据新品 | **合作方**（分销通路） |
| **S4** | 大型企业集团（类智问科技）的数字化/IT 部门 | 已有数仓或 BI，但业务部门仍然"找 IT 提数排队"，问数最后一公里没解决 | **直接买家**（灯塔型客户） |

**优先级判断**：S1 是价值主张的主锚点（痛点最痛、产品匹配度最高、智问科技即活样板）；S2/S3 是规模化杠杆（他们买的是"能拿去赚钱的成品"）；S4 客单价高但销售周期长、需定制，建议作为灯塔案例而非主打。

## 二、各细分 Jobs / Pains / Gains 拆解

### S1：飞书原生、无 BI 团队的中型企业（主锚点）

**Jobs（想完成什么）**
1. 老板/事业部负责人想随时问"这个月开单多少、哪个区域掉队了"，并拿到可信答案
2. 业务例会前快速出经营数据，不等 IT、不等数据专员
3. 多事业部、多层级组织（大区/分公司/城市公司）的逐级下钻对账
4. 把分散在几十张飞书多维表格里的数据变成"能问"的资产
5. 统一全公司指标口径，避免"财务一个数、销售一个数"

**Pains（最痛的阻碍）**
1. 没有预算/人头养 BI 团队（一个 BI 工程师年薪 30 万+，还不懂业务）
2. 上传统 BI（帆软/Tableau/PowerBI）：实施 3–6 个月起，报表做好业务已经变了
3. 试过通用 ChatBI 产品：接不了飞书多维表格，或接上了但口径全错，"AI 一本正经地胡说八道"一次，信任就归零
4. 数据散在多维表格里，IT 导出 Excel 手工拼，口径每次都不一样
5. 怕数据出司：核心经营数据不敢上公有云 SaaS

**Gains（想要的收益）**
1. 业务人员用大白话直接问数，秒级出结果，数字对得上账
2. 从"提数排期 3 天"变成"当场问当场答"
3. 数据不出内网（私有化部署），IT 放心
4. 指标口径一次定义、全司复用，新人不踩旧坑
5. 按成长型企业的预算付费，不为用不上的 BI 全家桶买单

---

### S2：数据咨询 / 实施服务商

**Jobs**
1. 快速给客户交付"AI 问数"能力，赶上 AI 项目的预算窗口
2. 把项目里的指标口径、错题、行业 know-how 沉淀成可复用资产，下个项目直接用
3. 压低每个项目的人天成本，提高毛利
4. 给客户讲得出"准确率怎么保障"的故事，过客户 IT 的验收

**Pains**
1. 每个项目从零写 NL2SQL，6 个月交付期，回款慢、风险全在自己身上
2. 自研的 NL2SQL 准确率不稳定，验收时被客户的业务问题问倒
3. 项目知识全在交付工程师脑子里，人走即失
4. 市面 ChatBI 要么是封闭 SaaS（没法私有化交付），要么是大厂平台（自己沦为纯人力外包）

**Gains**
1. 拿到一个可私有部署、可二次开发的成熟底座，项目周期从 6 个月压到 4–6 周
2. 错题库 + 口径手册的方法论可直接复用，形成自己的行业模板
3. 有真实集团客户（智问科技）背书，投标/PoC 成功率高
4. 按项目或分成模式合作，轻资产扩张

---

### S3：SaaS 渠道商 / 代理商

**Jobs**
1. 给存量企业客户找到高客单价、有差异化的 AI 新品，完成年度业绩
2. 卖"交付简单、售后不炸"的产品，保护自己在客户那里的信誉
3. 用厂商提供的演示、案例、话术快速开单

**Pains**
1. 手里的产品线同质化（又是 CRM/OA/费控），客户没有新预算理由
2. AI 产品大多是公有云 SaaS，数据敏感型客户根本不让装
3. 怕卖半成品：客户一问错数就来找渠道，砸的是自己招牌
4. 厂商支持力度弱，Demo 环境、报价、交付都要渠道自己扛

**Gains**
1. 一个有真实标杆案例、可私有化部署的 AI 数据产品，给客户创造新预算理由
2. 标准化 Docker 交付，渠道技术门槛低
3. 清晰的分润与区域保护，卖得越多越值
4. 错题库驱动的质量体系 = 可量化的准确率承诺，敢对客户拍胸脯

---

### S4：大型企业集团数字化部门（灯塔）

**Jobs**
1. 在已有数仓/BI 之上，解决业务部门"自助问数"的最后一公里
2. 统一全集团指标口径，消灭"各事业部各说各话"
3. 向管理层证明 AI 落地的实际成果（数字化部门自身的 KPI）

**Pains**
1. BI 报表做了几百张，业务还是"找人提数"，报表打开率惨淡
2. 大模型直接接生产库：口径错、权限乱，IT 不敢放行
3. 采购大厂 ChatBI 要与自家数仓/权限体系深度改造，项目失控风险高
4. 数据安全合规红线：核心经营数据不出域

**Gains**
1. 不动现有数仓，叠加一层"会业务口径的 AI 问数层"，快速见效
2. 私有化部署 + 语义层管控，IT 可控、可审计
3. 从"做报表的部门"升级为"AI 数据服务平台"，提升部门地位
4. 有可参观、可访谈的同行标杆（智问科技）降低决策风险

## 三、核心价值主张

### 主主张（1 句）

> **DataPulse 是长在飞书数据上的企业级智能问数平台：不动你现有的表格和数仓，让业务人员用大白话直接问到"对得上账"的经营数据——私有化部署，今天装、明天问。**

### 三条支撑

1. **口径对得上账，才敢用。** 语义层注入业务口径手册 + 100 大经典错题库驱动的质量工程，把"AI 算错数"这个 ChatBI 最大死因变成可验证、可承诺的准确率（智问科技消费者事业部实测 5/5 与真账 100% 吻合）。
2. **飞书原生，数据零搬迁。** 多维表格全量/增量自动同步进 PostgreSQL 语义层，业务人员不离开飞书工作流；不像传统 BI 要先做 3 个月数据治理，也不像通用 ChatBI 接不上多维表格。
3. **Docker 私有化部署，开箱即用。** PostgreSQL + 后端 + 前端一键容器化交付，数据不出内网；中型企业没有 BI 团队也能装，ISV/渠道商拿去就能交付。

### 差异化点强度标注

| 差异化点 | 强度 | 说明 |
|---|---|---|
| **业务口径手册 + 错题库驱动的质量工程** | ⭐⭐⭐ 最强 | 对手可抄四 Agent 架构，抄不走"从真实集团业务里长出来的口径与错题资产"；直接回应"AI 算错数"这一买家最大恐惧 |
| **飞书多维表格原生同步 + 私有化部署组合** | ⭐⭐⭐ 最强 | 精准卡位"数据在飞书、又不敢上公有云"的空白市场；大厂看不上（要接自家生态），小厂做不到（工程量大） |
| **真实集团落地案例（智问科技：3 大事业部、83 业务代表、全口径手册）** | ⭐⭐ 强 | B2B 买单的第一信任状；但不是产品本身，需转化为案例资产 |
| 四 Agent 分工架构 | ⭐ 中 | 对买家是"听不懂的技术词"，但对 ISV/技术评估人是可维护性证据，留给技术白皮书用 |
| Docker 容器化 | ⭐ 中 | 是交付成本的竞争力，单独说没有感知度，要翻译为"今天装、明天问" |

## 四、买家愿意付钱的 vs 技术人自嗨的

### ✅ 愿意付钱的卖点（进价值主张/报价页）

1. **"数字对得上账"** —— 准确率可验证、有真实对账记录。这是所有 ChatBI 采购决策的生死项，直接决定签单。
2. **"不等 IT，业务自己问数"** —— 省的是 BI 人力（30 万+/人/年）和提数排期，ROI 好算。
3. **"数据不出内网"** —— 私有化部署是准入门槛级卖点，没有它连 PoC 资格都没有。
4. **"飞书里的数据直接能问"** —— 零数据搬迁、零工作流改变，对飞书客户是即插即用的感知。
5. **"今天装、明天问"** —— 交付周期从月级压到天级，对 ISV/渠道商等于毛利提升。
6. **"智问科技在用"** —— 真实标杆案例，B2B 成交的第一信任杠杆。

### ❌ 技术人自嗨的卖点（别放买家面前）

1. **"四 Agent 架构"** —— 业务买家无感，只关心"问得准不准"。（留给 ISV 的技术评估文档。）
2. **"JSONB 物理表 + 展平视图 + Bookshelf 语义层"** —— 纯实现细节，说出来只增加认知负担。
3. **"190 个 py、31 个 vue 文件的工程规模"** —— 代码量不是价值，甚至是"维护成本"的负面信号。
4. **"全量/增量同步机制"** —— 买家只关心结果："数据是不是新的"，机制本身不加分。
5. **"NL2SQL / Agentic Analytics 概念"** —— 行业黑话，说给投资人听可以，说给买水的厂长听是减分项。

## 五、对商业模式设计（阶段 04）的 3 点输入建议

1. **定价锚点选"省一个 BI 人力"，而不是"对标 BI 软件 license"。** S1 客户的替代方案是"招人或忍痛点"，年费定在 10–25 万区间最容易算账；对 S4 灯塔客户则可按事业部/数据域模块加价。建议阶段 04 按"软件年费 + 首年口径实施费"两段式设计，错题库/口径手册的实施过程本身就是高价值服务。
2. **S2（ISV/实施商）是最快的规模化通路，但必须在合作方案里锁死两件事：① 口径手册与错题库等知识资产的归属权留在创始方；② 禁止合作方基于 DataPulse 白牌转售。** 这是本产品唯一不可再生的护城河，阶段 04 设计分成模式时要以"资产不外流"为前提谈让利多寡。
3. **渠道商（S3）政策设计要把"准确率承诺"产品化。** 建议把实测体检报告做成标准化的《准确率验收清单》作为交付物——这既给渠道敢卖的底气，也把售后争议变成有据可查的验收流程，避免渠道被客户问题反噬后波及创始方。
