## 一、五种合作方案

五种方案覆盖五种不同的合作逻辑：**自己卖、给人当军火、借人通路、联合打单、托管收租**。定价统一锚定阶段 03 结论——"省一个 BI 人力（30 万+/年）"，S1 终端客户年费 10–25 万区间，采用"软件年费 + 首年口径实施费"两段式。

### 方案 1：「自营旗舰」—— 创始人直销 + 主导交付

| 维度 | 内容 |
|---|---|
| **合作结构** | 无合作方。创始人直接对接终端客户（S1 中型企业、S4 灯塔集团），直接签约、直接交付、直接收款 |
| **双方分工** | 创始人包揽：售前 PoC、私有化部署、口径实施（把客户业务口径写进语义层+错题库）、售后 |
| **收费模式** | 软件年费 12–20 万（按数据域/事业部数量分级）+ 首年口径实施费 5–10 万（一次性）；次年续费 = 纯软件年费 |
| **适用场景** | 0→1 阶段必须走通的路径；前 3–5 个客户全部自营，把交付方法打磨成可复制 SOP；S4 灯塔客户永远自营（客单价高、战略价值大，不可假手他人） |
| **最大风险** | 创始人是企业员工、业余创业，**时间和精力是硬天花板**，自营模式天然无法规模化；且直销积累的客户关系、口径资产全部依赖个人，一旦本职工作冲突，生意停摆 |
| **风险对冲条款/动作** | ① 前 3 单不求赚钱，求把"部署+口径实施+验收"做成标准作业包（见改进计划 P0/P1）；② 每单交付物必须沉淀为资产（行业口径模板、错题库增量），让"交付"变成"攒资产"而不是"卖时间"；③ 合同中加入"标准交付清单 + 验收标准"（准确率验收清单），把售后争议关在验收流程里 |

### 方案 2：「军火商」—— ISV/实施商授权交付（License 授权，不交源码）

| 维度 | 内容 |
|---|---|
| **合作结构** | 创始方做"军火商"：向数据咨询公司/实施商（S2）授权 DataPulse 私有化部署 License + 实施方法论；ISV 拿去做自己的客户项目 |
| **双方分工** | ISV：找客户、签约、前端实施与定制、一线售后；创始方：提供安装包、License 授权、口径实施方法论培训、二线技术支持、产品迭代 |
| **收费模式** | 双轨：① 每项目 License 费 5–8 万/客户/年（ISV 代付，ISV 对客户加价）；② 或项目分成：创始方抽终端合同额的 20–30%；③ 方法论认证培训费（一次性 2–5 万/家）作为准入门槛与筛选器 |
| **适用场景** | 最快的规模化通路。S2 自己就是"每个项目重写 NL2SQL"的痛点人群，DataPulse 对他们是从 6 个月压到 4–6 周的印钞机 |
| **最大风险** | **资产外流**：ISV 在交付中吃透口径手册/错题库方法论后，绕开创始方自研或白牌转售，"别人赚钱我当嫁衣"的最大案发地 |
| **风险对冲条款** | ① **知识资产归属条款**：口径手册、错题库、语义层方法论的著作权归创始方，ISV 仅在授权项目范围内获得使用权；ISV 在项目中新增的口径/错题资产，归属权归创始方、ISV 获得该项目内的使用权（这一条可谈，但"原始资产不外流"不可谈）；② **禁止白牌条款**：不得去除品牌、不得基于 DataPulse 或其方法论开发竞品/转售第三方；③ **不交源码**：只交付 Docker 镜像 + License Key，核心模块（语义层/错题库引擎）编译闭源；④ 违约罚则 + 审计权（见第三部分） |

### 方案 3：「通路杠杆」—— 渠道分销返佣

| 维度 | 内容 |
|---|---|
| **合作结构** | 与 SaaS 渠道商/代理商（S3）签分销协议：渠道负责获客签单，交付可"渠道交付"或"回传创始方交付"两种形态 |
| **双方分工** | 渠道：获客、商务、签约收款（对客户）；创始方：标准产品包、演示环境、案例白皮书、报价支持、交付与售后（或培训渠道自己交付） |
| **收费模式** | 标准价格表 + 阶梯返佣：渠道按目录价 6–7 折拿货（返佣 30–40%），年回款额达标升级折扣档位；设区域/行业保护期（首签保护 6–12 个月），防止渠道互相杀价 |
| **适用场景** | 已有标准化产品包（安装包+License+验收清单齐备）之后启动；适合覆盖创始人够不着的区域市场与存量客户池 |
| **最大风险** | 渠道卖半成品砸招牌→客户问题反噬创始方；渠道低价甩卖扰乱价格体系；渠道掌握客户关系后绕过创始方直签（飞单） |
| **风险对冲条款** | ① **准确率承诺产品化**：每单交付必带《准确率验收清单》，渠道只承诺清单内的东西，超纲需求回传创始方，把售后争议关进验收流程；② **报备制**：渠道商机必须报备锁定，客户名单同步创始方备案，未报备成交不享受返佣，飞单则取消代理资格；③ **最低成交价（MAP）条款**：低于底价销售取消返佣直至解约；④ 首年渠道只卖"标准包"，定制需求一律回流创始方报价 |

### 方案 4：「联合舰队」—— 与咨询公司联合交付分成

| 维度 | 内容 |
|---|---|
| **合作结构** | 与管理咨询/数字化咨询公司组成联合体打单：咨询方出客户关系、行业 know-how、业务口径梳理能力；创始方出 DataPulse 产品与实施 |
| **双方分工** | 咨询方：商务关系、需求梳理、指标口径定义（业务侧）；创始方：产品部署、语义层注入、错题库测试、技术验收 |
| **收费模式** | 按项目合同额分成：咨询方 40–50%（客户关系溢价），创始方 50–60%（产品+交付）；或咨询方买断交付权（打包价），超出部分归咨询方 |
| **适用场景** | 客单价 30 万+ 的大单、需要"咨询+软件"组合投标的场景；创始人暂无销售团队时借咨询公司的商务能力 |
| **最大风险** | 咨询方掌握客户关系，项目结束后客户被咨询方带走，后续增购/续费与创始方无关；咨询方在合作中习得方法论后自研 |
| **风险对冲条款** | ① **合同结构**：尽量与客户签三方协议，或至少软件 License 合同由客户与创始方直签（软件年费这条命脉必须直连客户）；② **续约归属条款**：License 续费归创始方，咨询方仅对新增咨询/实施服务收费；③ **方法论隔离**：咨询方接触的是"业务口径梳理"层，语义层实现与错题库工程细节不开放；④ 客户名单共享备案，单方私下撬单有违约金 |

### 方案 5：「托管收租」—— 私有化部署 + 创始方远程托管订阅

| 维度 | 内容 |
|---|---|
| **合作结构** | 产品仍是私有化部署（数据不出客户内网，满足 S1/S4 安全红线），但运维层由创始方远程托管：客户不养运维，创始方按月/年收"软件+托管"订阅费。可叠加渠道做前端销售，创始方做后端托管 |
| **双方分工** | 客户/渠道：商务与使用；创始方：远程升级、错题库持续运营（每月错题回归）、口径维护、SLA 响应 |
| **收费模式** | 年订阅 15–25 万/年（含 License + 托管运维 + 错题库季度更新 + 口径微调额度），实施费另计；超出口径调整额度按人天计费 |
| **适用场景** | S1 客户"没有 BI 团队"痛点的终极形态——连运维都不想要；也是把一次性买卖变成年金型收入的关键改造 |
| **最大风险** | 托管 = 持续人力投入，创始人业余时间被售后拖死；远程运维涉及客户内网准入，安全合规门槛高；订阅定价过低会沦为"包年保姆" |
| **风险对冲条款/动作** | ① **SLA 分级**：标准版（工作日响应/48h）与旗舰版（7×24/4h）价差 50%+，把"随叫随到"卖成奢侈品；② 托管范围白名单化：只含升级/回归/口径微调，不含"帮做报表、帮导数据"等无限服务，超出走人天计费；③ 远程接入走 VPN/堡垒机，操作留痕可审计（这也是对客户 IT 的卖点）；④ 错题库运营做成半自动化流程后再放开托管客户数，先 3 家试运行 |

### 五种方案的组合使用建议

- **0→1 期（现在）**：方案 1 为主，跑通 2–3 个自营客户，攒 SOP 与案例。
- **1→10 期**：方案 2 + 方案 4 并行——军火商走量、联合舰队打大单；方案 5 作为收费模式改造叠加在所有方案上。
- **10→N 期**：方案 3 放量，渠道政策只有在产品包完全标准化后才启动，否则会售后失血。
- 五条线共用同一条底线：**License 续费合同尽量与客户直签，知识资产归属寸步不让。**

## 二、商业化改进计划（产品化改造清单）

把"智问科技内部项目"改造成"可卖商品"，按优先级排序。工作量分级：**S = 1–2 周 / M = 3–6 周 / L = 2 个月+**（按业余创业时间预算折算）。

### P0 —— 没有就卖不了（阻塞项）

| # | 改造项 | 说明 | 工作量 |
|---|---|---|---|
| 1 | **License 授权机制** | License Key 生成/校验/到期控制/按数据域授权。没有它，方案 2/3/5 全部无从谈起，也是权益保护的技术底座 | **M** |
| 2 | **《准确率验收清单》产品化** | 把智问科技实测体检报告改造成标准交付物：验收问题集模板 + 通过率标准 + 双方签字确认流程。是定价底气，也是售后防火墙 | **S** |
| 3 | **去智问科技化的演示环境 + 案例白皮书** | 用脱敏/虚构数据搭一个公开 Demo（现有数据涉及真实企业，直接演示有合规风险）；案例白皮书需获得智问科技书面授权（见第三部分职务作品章节） | **M** |
| 4 | **标准安装包打磨** | Docker 一键部署已有基础，补齐：环境自检脚本、初始化向导、常见问题手册，目标是"ISV 工程师看文档 2 小时装完" | **S** |

### P1 —— 影响规模化（重要项）

| # | 改造项 | 说明 | 工作量 |
|---|---|---|---|
| 5 | **标准定价表与报价器** | S1/S2/S3/S4 四套价目：软件年费分级（按数据域/用户数）+ 实施费 + 托管订阅档 + 渠道折扣阶梯。一张纸能报完价 | **S** |
| 6 | **核心模块闭源改造** | 语义层引擎、错题库质量工程模块编译/打包为不可读产物，业务层代码可开放（方便 ISV 定制）。权益保护的技术落地 | **M** |
| 7 | **交付 SOP 手册** | 部署→数据接入→口径实施→错题回归→验收，五步标准作业包，把方案 1 的交付经验变成方案 2/3 可培训的材料 | **M** |
| 8 | **合同模板包** | 直销合同、ISV 授权协议、渠道分销协议、NDA、准确率验收单——五套模板（律师审核后定型） | **S**（准备） |

### P2 —— 体验与效率（增强项）

| # | 改造项 | 说明 | 工作量 |
|---|---|---|---|
| 9 | **售后 SLA 分级体系** | 标准/旗舰两档 SLA + 工单通道 + 远程运维接入规范（方案 5 的前置） | **S** |
| 10 | **多实例管理能力** | 同一客户多事业部/多数据域的实例编排；为 S4 灯塔客户和托管模式铺路 | **L** |
| 11 | **行业口径模板包** | 把智问科技口径手册抽象为"制造业/消费品行业通用口径模板"，让下一家实施周期从月压到周 | **L**（持续运营） |
| 12 | **品牌与官网落地页** | 产品名、Logo、一页式落地页（主主张 + 三支撑 + 案例 + 留资），渠道和 ISV 都需要这个弹药 | **S** |

**路线判断**：P0 四项完成 = 可以开始签方案 1 和方案 2 的单；P1 完成 = 可以放量；P2 按需迭代。**不要在 P0 之前启动渠道招商。**

## 三、创始人权益保护设计（"不当嫁衣"条款清单）

### 3.1 IP 与知识资产归属

- **软件著作权**：尽快以创始人个人（或个人持股主体）名义登记 DataPulse 软著；口径手册、错题库作为**文字作品/汇编作品**单独登记或留存带时间戳的创作证据（Git 提交记录、可信时间戳）。
- **资产分层归属**（所有合作协议的标配条款）：
  - 第 1 层（寸土不让）：DataPulse 软件本体、语义层引擎、错题库工程体系、通用方法论 → 永远归创始方。
  - 第 2 层（可授权不可转让）：行业口径模板 → 合作方获使用权，不得反向工程、不得用于授权项目之外。
  - 第 3 层（可谈）：项目中新生成的客户专属口径 → 归属创始方、客户获永久使用权；或归客户、创始方保留抽象为通用模板的权利。
- **明确"禁止白牌 + 禁止反向工程 + 禁止用于训练竞品"**三禁条款进所有授权协议。

### 3.2 源代码保护手段

| 手段 | 做法 | 防什么 |
|---|---|---|
| **License 授权而非源码交付** | 默认只交付 Docker 镜像 + License Key；源码交付只在大客户买断场景下单独天价谈判 | 日常合作中的代码外流 |
| **核心模块闭源** | 语义层/错题库引擎编译闭源，业务层可开放 | ISV 吃透核心逻辑后自研 |
| **代码托管 Escrow** | 大客户要求"厂商倒闭了怎么办"时，用第三方源码托管（escrow）替代直接交源码——触发条件（破产/停止维护）才释放 | 既成单又不外流 |
| **License 内埋水印** | 每个 License 绑定客户标识，镜像内嵌不可见指纹 | 镜像被拷贝转卖时可溯源举证 |

### 3.3 保密与竞业条款

- 所有合作先签 NDA 再谈细节；NDA 覆盖"口径手册、错题库、定价体系、客户名单"四类机密。
- 对 ISV/咨询方加**竞业限制**：合作期 + 终止后 12–24 个月内，不得基于 DataPulse 方法论开发/代理同类 NL2SQL 问数产品（注意竞业条款的合理范围，过宽会被认定无效——**需律师把握尺度**）。
- 对接触核心实施的渠道技术人员，签个人保密承诺。

### 3.4 分账对账与审计权

- 所有分成模式（方案 2/3/4）写入**对账条款**：合作方按季度提供终端合同清单与回款凭证。
- 写入**审计权**：创始方有权每年一次委托第三方审计合作方相关账目，发现少报/飞单的，补付 + 违约金（建议 2–3 倍差额）。
- 商机报备制 + 客户名单备案制（方案 3 已述），名单备案 = 后续维权证据。

### 3.5 客户名单归属

- 方案 2/3/4 的所有终端客户名单，双方共享备案；**软件续费权归创始方**是铁律。
- 合作终止后：存量客户的 License 续费与运维归创始方接管（客户软件合同最好是客户与创始方直签，从结构上锁死）；合作方不得将客户导向竞品，违约有明确罚则。

### 3.6 退出与终止机制

- 所有协议设**锁定期**（首年不可无因解约）+ **提前通知期**（90 天）。
- 终止触发条件清单化：飞单、白牌、低价窜货、泄密、少报分账——触发即"立即终止 + 罚则"，无需协商。
- 终止后义务：License 立即失效（技术支持到期）、机密资料返还/销毁、存量客户移交创始方。

### 3.7 ⚠️ 职务作品风险隔离（创始人最优先处理项）

创始人是**企业战略运营部在职员工、业余自研**，这是所有商业化动作的前置风险，必须先排雷：

1. **梳理劳动合同与员工手册**：重点看"职务作品/职务发明"条款。如果 DataPulse 的开发"使用了公司资源（设备/数据/时间）"或"属于本职工作范围"，公司可主张权利——**尤其 DataPulse 就是在公司（智问科技）业务中长出来的，这条风险是现实而非理论**。
2. **建议动作**（按优先级）：
   - ① 与公司法务/管理层**书面确认 DataPulse 及商业化行为的归属与许可**——最理想是拿到"公司确认该作品为个人非职务作品"或"公司授权个人商业化"的书面文件；
   - ② 若无法拿到书面确认，考虑将后续商业化版本与在职期间版本做**切割**：以离职后/独立主体名义重写核心模块的增量部分，保留完整独立开发证据链（个人设备、个人时间、个人仓库）；
   - ③ 设立个人持股的独立主体（公司或个体户）作为商业化签约主体，与个人雇主做任何交易都回避利益冲突。
3. **智问科技案例背书的使用边界**：品牌露出（"智问科技在用"）与真实经营数据是两个层级。数据绝不对外（脱敏也不行，除非书面授权）；品牌背书需公司书面同意，否则白皮书改用"某头部净水集团"匿名表述。
4. **本章节内容尤其需要律师介入**：职务作品认定因合同约定与事实细节差异极大，以上仅为风险地图，不是法律结论。

## 五、Top 3 高风险假设（待 MVP 阶段优先验证）

1. **付费假设**：S1 客户真的愿意为"问数"付 10–25 万/年，而不是继续人肉导表忍着？——用 3 个自营 PoC 转化率和议价过程验证真实付费意愿。
2. **可复制假设**："口径实施"能从创始人手艺变成 ISV 工程师照 SOP 就能干的标准动作？——用第一个 ISV 认证项目验证交付周期能否压进 4–6 周。
3. **权属假设**：DataPulse 的职务作品边界能厘清（拿到书面确认或完成切割），商业化主体合规成立？——这条不验证，前面两条成了也白搭。
